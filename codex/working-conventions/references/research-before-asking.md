# Research a question before asking it

Applies before putting any question or decision to the user, in any project.

1. **Research it first.** Read what the project already holds (its code,
   records, prior decisions, private sources), then gather current external
   practice where the question is one others have faced. Do this before
   writing the options, not after the user answers.
2. **Present the evidence with the question.** Each option says what supports
   it and what it costs, with the source named.
3. **The recommendation is the option the research found best**, stated as
   such, not the most convenient one or a guess. Where the evidence is thin or
   split, say so in the question rather than implying confidence.
4. **Ask through the host's structured question prompt**, one answerable
   question per item, not as prose at the end of a reply. Where the host has
   none, number the questions and give each its options.
5. **A purely procedural question** (approve this commit, this push) needs no
   external survey, only the facts the user decides from.

**If a question already asked was not researched to this standard, revisit
it:** do the research, and ask it again if the best option changed.

## Why

The user's attention is the scarce resource, and a question costs it twice
when the answer is already in the project or is settled practice elsewhere.
An unresearched recommendation reads as a finding but is a guess, so the user
either re-does the research or decides on less than the agent could have
found. Evidence beside each option lets the user decide in one pass, and a
structured prompt keeps each decision separate and on the record instead of
buried in a paragraph.
